# 原创教学夹具

`corpus/` 的 30 份中文 Markdown 和 `eval/questions.jsonl` 的 60 条问题是为 DevDocQA 编写的简短教学资料。它们不是收集的企业文档、招聘试题、真实用户数据或公认 benchmark。知识范围有意收窄，用于调试数据流、检索、引用与无答案行为；不能用结果证明行业或生产环境效果。

## 数据约定

- 文档文件名为 `NN-topic.md`，文档内使用 `DOC-NN` 编号，引用时保留原文件名。
- 问题字段：`id`、`split`、`category`、`question`、`expected_document_names`、`reference_answer`。
- `category` 为 `direct`（40 条）、`multi_document`（10 条）、`unanswerable`（10 条）。
- `split` 为 `dev`（20 条：14/3/3）或 `test`（40 条：26/7/7），对应上述三类顺序。
- 无答案题的 `expected_document_names` 为空列表；正确行为是说明资料未提供相关事实，不编造答案。
- 参考回答由作者编写，并非真实模型输出或已测量分数。

## 如何使用

1. 阅读根目录启动说明，上传所有文档，等待每个入库任务成功。
2. 先使用 dev 的 20 题调试，查看召回片段与引用；不要用 test 的参考答案调参。
3. 固定模型、分块、检索与生成配置后，在 test 40 题上运行并保存原始输出和配置。
4. 对可回答题统计文档级 Hit@5：direct 题命中其期望文档；multi_document 题需要前五片段覆盖全部期望文档。也分别报告两类结果，避免多文档题被单命中掩盖。
5. 人工判定答案是否正确、引用是否支持答案；对无答案题单独记录“依据不足”识别率。只看回答与参考答案字符串相似度不够。
6. 报告错误类别：检索漏召回、上下文丢失、生成错误、引用不支持、无答案幻觉。Mock 输出只验证流程，不参与真实问答正确率。

这套资料过短且内容容易记忆，学习后应扩展到有权使用、含复杂结构的真实技术资料再评估。问题文件可供开发者检查，但正式测试时隔离 test 参考答案，防止其进入检索库或提示词。仅上传 `corpus/*.md`，不要上传题集或答案文件。

## 独立练习

先读文档，用自己的话解释，再写一个小实验验证。每周挑一条回答错误，手工判断应检索哪些文档，提出修复假设并用 dev 验证。不要让 AI 自动修改 test 参考答案以匹配模型输出。
